# Evidence: fused scanline reconstruction (Phase 1, branch `fused-decode-frontier`)

**Provenance:** written by the PhotoshopAPI-rs port team. This document is **ours**, not upstream
png-spark; it lives in this working checkout so the implementing agent has everything in one place.
**Subject:** commit `ec53075` + `0dbc3dc` on `fused-decode-frontier` (base `6d256fc`, main at PR #1).
**Companion documents:** `DESIGN-banded-decode.md` (proposal), `TODO.md` (tracking, gitignored).

---

## 1. What changed

`Decoder::decode` for non-interlaced images inflates the filtered stream and then reverses the
scanline filters in a second pass. On images beyond the caches that second pass reads every row
long after inflation evicted it. The branch fuses the two: a `ReconstructionFrontier`
(`src/filter.rs`) reverses each row in place as inflation's output cursor passes it, lagging the
cursor by DEFLATE's match window so no future match can read a byte reconstruction has rewritten.
Streams no larger than one window plus one row can never trigger mid-inflation reconstruction and
take the plain two-pass path unchanged, so small decodes pay nothing.

- Hot-loop cost: one compare per decode-loop iteration, compiled out entirely (`const ENABLED`)
  for every entry point except the decoder's non-interlaced path.
- Public API: unchanged. `decode()` output is byte-identical to `main`.

## 2. Methodology

The machine thermally throttles on sustained benchmarks (observed >30 % swings on mean decode
times), so every comparison follows the design doc's rules:

- **Interleaved**: arms alternate process-by-process, round by round. A round is one full pass of
  the stage profiler (`bench/src/bin/profile.rs`) over the fixture set per arm.
- **Best-of-N per round, min across rounds**: the profiler takes each fixture's best decode time
  within a ~400 ms wall-clock budget; the harness (`%TEMP%\opencode\ab_decode.py`) keeps each
  arm's per-fixture minimum across 6 rounds.
- **One session**: all numbers below come from single uninterrupted runs; nothing is compared
  across sessions.

**Noise floor, measured the same way:** running `main` against `main` for 3 rounds produced
byte-identical minima for every fixture — delta **+0.00 %** across the board. The best-of
statistic on this machine is far more stable than the means, so deltas below ~1 % are still
meaningful, and the small-file suite (§5) is read at 100 ns granularity for exactly that reason.

**Fixtures:** `tmp/large/*.png`, generated by `tools/gen_large_fixtures.py` (CPython's zlib — a
full LZ77 match finder — filters and compresses each). This matters: png-spark's *own* encoder
emits zero-run, distance-1 matches only, and all 180 reference-corpus images are smaller than the
32 KiB match window, so neither can detect a frontier whose lag is wrong. Every `tmp/large`
fixture exceeds the window; the largest is 36.9 MB filtered. Corpus fixtures (`tmp/png`, 180
files from `tools/gen_testdata.py`) cover the small-file domain.

## 3. Large-image A/B: 9/9 faster

Branch vs `main`, interleaved best-of-6, single session, noise floor ±0.00 %:

| fixture | filtered | main ms | branch ms | delta |
|---|---:|---:|---:|---:|
| rgba8_photo_3840x2400 | 36.9 MB | 52.27 | 47.60 | **−8.9 %** |
| rgb8_photo_2048 | 12.6 MB | 18.03 | 17.11 | −5.1 % |
| rgba16_gradient_1024 | 8.4 MB | 2.03 | 1.91 | −5.9 % |
| rgba8_gradient_1024 | 4.2 MB | 5.55 | 5.19 | −6.5 % |
| rgba8_mixed_1024 | 4.2 MB | 4.29 | 4.17 | −2.8 % |
| rgba8_noise_1024 | 4.2 MB | 2.24 | 2.20 | −1.8 % |
| rgba8_wide_4096x96 | 1.6 MB | 2.11 | 1.99 | −5.7 % |
| rgba8_tall_64x4096 | 1.1 MB | 1.37 | 1.27 | −7.3 % |
| gray8_gradient_1600 | 2.6 MB | 1.04 | 1.01 | −2.9 % |

Reading:

- The headline number is the port's dominant class: RGBA8 4K, the exact shape smart-object
  rasters arrive in (13 of 13 PNGs in the port's corpus are RGBA8 non-interlaced).
- The noise fixture (−1.8 %) is the conservative floor: literals dominate, so the frontier's
  per-iteration check is at its densest and the second pass it eliminates was at its cheapest.
- Both shape extremes (16 KiB rows × 96, 257 B rows × 4096) win, so the gain is not an artifact
  of one row size.
- The spread (−1.8 % … −8.9 %) sits inside the design doc's promised 5–15 % band for large
  images, biased low by fixtures whose second pass was only partially cold.

## 4. Small-file A/B: equal within the measurement floor

Ten fixtures bracketing the 32 KiB window and below (5 interleaved rounds, best-of-3000 per
fixture, printed in nanoseconds; harness `%TEMP%\opencode\ab_small.py`):

| fixture | main | branch | delta |
|---|---:|---:|---:|
| rgba8_small_64x184 (47 KB, over window — fused) | 58 500 ns | 58 400 ns | −0.2 % |
| rgba8_small_64x92 (24 KB, under window — legacy path) | 30 400 ns | 30 800 ns | +1.3 % |
| ct2_d8_i0_63x40 | 4 600 ns | 4 600 ns | +0.0 % |
| ct2_d8_i0_32x17 | 1 600 ns | 1 600 ns | +0.0 % |
| ct0_d1_i0_63x40 | 500 ns | 600 ns | +20 % (one 100 ns bucket) |
| five ≤1 px–9 px corpus files | 300–1 800 ns | identical | +0.0 % |

Reading:

- Below the window gate the branch runs the **byte-identical legacy code path**; residual deltas
  at this scale are the benchmark layout lottery, not the feature (the +20 % row is +100 ns on a
  500 ns decode, one measurement bucket, on a path with no frontier code in it).
- The 47 KB file just over the threshold nets to −0.2 %: fusion's savings and the polling cost
  cancel at that size, which is exactly where the gate belongs.

## 5. Correctness gates (all green on the final commit)

| gate | result |
|---|---|
| `cargo test -j 2` (workspace, 15 test binaries) | all green |
| reference corpus, 180 files (`tools/gen_testdata.py`) | byte-exact, 180/180 |
| **fused vs legacy path** (`tests/fused_reconstruction.rs`, 9 zlib fixtures ≤ 36.9 MB) | byte-exact, 9/9 |
| frontier unit tests (filters × strides × Paeth-run alignments, fired-mid-inflation, invalid-filter freeze) | 10/10 |
| `cargo clippy --all-targets` | clean |
| `cargo fmt --all --check` | clean |
| Miri over the filter tests (nightly) | green |

Two real bugs were caught by these gates during development, both invisible to the pre-existing
suite: the tail drain initially kept the lag precondition (unsatisfiable below one window, so
every small image would have been left unreconstructed), and the Adam7 arm was left uninflated
when the shared inflate block moved (87 corpus failures). The 180-file corpus alone cannot see
either bug class for this feature — see §2 — which is why the zlib-generated large fixtures and
the fired-mid-inflation assertions exist.

Not run here: `cargo fuzz` targets (need nightly + cargo-fuzz; the `inflate` and `decode` targets
should pass unchanged since `()`-hook entry points compile to the old loop, but they should be run
before any upstream PR).

## 6. Reproduce

```sh
python3 tools/gen_testdata.py       # reference corpus
python3 tools/gen_large_fixtures.py # this document's fixtures
cargo test -j 2
cargo run --release -p png-spark-bench --bin profile -- tmp/large
```

The A/B harnesses live outside the repo (`%TEMP%\opencode\ab_decode.py`, `ab_small.py`); the
`main` arm was built from a `git worktree` of `6d256fc` at `..\png-spark-main`.
